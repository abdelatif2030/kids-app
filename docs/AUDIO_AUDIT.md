# Audio audit (2026-10-29)

Checked against the repository at the time of writing (branch `feature/rehlaty`). Nothing here was verified on a real
phone, speaker or browser unless a line says so. See `docs/AUDIO_COVERAGE.md` for the numbers (generated from the real
manifest, not typed by hand).

## 1. What already works (code and tests)
- **One lesson audio service** (`lib/media/audio_service.dart`, `AppAudio.service`): one clip at a time, real states
  (idle, loading, playing, paused, completed, error), the reason when nothing is heard (voice off, missing, no voice,
  recording failed, failed, **in a call**), replay, stop, slow speed, token-guarded so a late result never plays.
- **Honest content catalog** (`lib/media/audio_manifest.dart`): 360 items built from the real content (Arabic letter
  names, 84 isolated sounds, 78 words, 11 numbers; English 26 letter names, 26 phonics, 107 words) with statuses
  missing / discovered / generated / awaiting audio review / awaiting language review / approved / rejected /
  needs re-check. **Approval needs a file, a confirmed license, an audio reviewer and a language reviewer.** Isolated sounds
  and phonics can never be voiced by a device voice.
- **Parent tools**: audio status per item, review screens, voice comparison, audio settings (voice on/off, speed
  0.75/1/1.25, allow device voice, ambient sound and volume, stories in quiet hours).
- **Stories** (`lib/stories/story_player.dart`): file or device voice, play/pause/seek/skip/speed, sleep timer, ambient,
  resume; never autoplays another story.
- **Tests**: audio service, status, QA, review, stories, manifest validation, accessibility of the buttons.

## 2. What was missing or wrong, and what was done now
| Finding | Action |
|---|---|
| Lessons and stories could keep talking during a family call | `AudioGate` (`lib/media/audio_gate.dart`): a call stops lesson audio and stories, blocks new lesson audio with a message («مكالمة عائلية جارية»), and **nothing resumes by itself** afterwards. Tests in `test/audio_gate_test.dart` and `test/family_calls_test.dart`. |
| Lesson audio had no app-lifecycle handling | The same gate stops lesson audio and pauses stories when the app leaves the screen (paused / hidden / detached). No resume by itself. |
| No game used listening as the task | Three listening games on the shared `ChoiceGame`: listen and pick the picture (3-6), the written word (5-8), the letter by its NAME (4-6). Captions always visible, honest no-voice message, no punishment, one star on first completion. |
| No coverage report | `docs/AUDIO_COVERAGE.md`, generated by `test/audio_coverage_report_test.dart` from the real manifest. |
| Call screen did not say what is switched on | Banner: microphone on/muted, camera on/off. |
| A dropped call connection ended or hung | New `reconnecting` phase (15 s) that recovers by itself or ends with a clear message. |

## 3. What is real, generated, awaiting review or unavailable (today)
- **Human recordings: 0.** `assets/audio/ar/*` and `assets/audio/en/*` hold only `README.txt` placeholders.
- **Generated lesson files: 0.** `tools/audio_gen` exists (offline, key only from the environment) but has not been run
  against a real service.
- **Real audio files in the app: 4 ambient loops** (`rain`, `waves`, `wind`: synthetic noise; `musicbox`: a synthesized
  tune). They are sound effects, not speech.
- **Approved items: 0 of 360.** With the default settings a child would hear the **device demo voice** for 250 items
  and **nothing** (a message and the text on screen) for the 110 isolated sounds / phonics.
- **Stories:** device voice only (8 original texts), labelled as a demo; no narrated recordings.

## 4. Voices by platform
Cannot be verified from the cloud session (no Android, iOS, speakers or browser voices here).
- The code asks the device for `ar-SA`, then any `ar`, and `en-US`, then any `en` (`TtsSpeech`). A device with no Arabic
  voice reports "unavailable" instead of reading Arabic with another language's voice.
- Real availability and quality on Android phones, iPhone, Chrome, Edge, Safari and Firefox is **unknown until tested**:
  see the manual checklist (MANUAL_TESTS, section A-audio). A curated pronunciation test set already exists in
  `assets/audio/eval_set.json` (92 samples: letter names, sounds, shadda, tanween, sukoon, long vowels, numbers,
  similar letters, English phonics, stories, instructions). Every Arabic sample needs a qualified Arabic reviewer.
- Do not claim an accent (MSA, Egyptian, Gulf) is supported; the app only asks for `ar-SA` and takes what the device has.

## 5. Dependencies and their limits
| Package | Used for | Limit |
|---|---|---|
| `flutter_tts` | device voice | voices differ per device and browser; no word timing, so no read-along highlighting |
| `just_audio` | files (and playing voice messages) | web needs a user tap first; `StreamAudioSource` (play from memory on phones) is marked experimental |
| `record` | voice messages in chat | web needs HTTPS or localhost; encoder differs by platform |
| `flutter_webrtc` | calls | needs a TURN relay on some mobile networks |
No package was added in this pass.

## 6. Generation workflow (decision, nothing added)
Existing and sufficient: `tools/audio_gen` (compare voices from the eval set, generate DRAFT files only for missing items,
write them to the manifest as `generated`, never `approved`, never for isolated sounds). Reviewed human recordings remain
the target for letter names, sounds and words (`docs/AUDIO_RECORDING_SHEET.csv`). Using a cloud voice needs your approval
(`docs/AUDIO_DECISION.md`, `docs/AUDIO_PROVIDERS.md`); children's data is never sent to any speech service (only fixed
curriculum texts are).

## 7. Prioritized plan
1. Run the voice comparison on 2-3 real Android phones and one iPhone with the 92-sample set; note which devices have an
   Arabic voice and how it sounds. (You or a reviewer.)
2. Record or approve the Arabic letter names and the 78 words with a native speaker (recording sheet), then fill the
   manifest with real reviewers' names. Same for the English letter names and words.
3. Record the 84 Arabic letter sounds and 26 English phonics with a human speaker; synthetic voices may not be used.
4. Only then consider read-along highlighting (needs reviewed timings) and a pronunciation helper (needs a reliable
   method; none is claimed).
5. TURN server decision for calls on mobile networks.

## 8. Recording and review checklist
- [ ] One speaker per language, same microphone and room, no clipping, similar loudness.
- [ ] Letter names (باء) are not letter sounds (بَ); sounds are one short syllable without an extra vowel.
- [ ] MSA, no dialect, unless a lesson says otherwise. Check hamza, shadda, tanween, sukoon, long vowels.
- [ ] English: one locale (US), same for all items; phonics are pure sounds ("b", not "buh").
- [ ] File name = `suggestedFile` of the item; license written (for example "original, owned by the app").
- [ ] Two different people decide: audio quality and language. Names and date go into `assets/audio/manifest.json`.
- [ ] Re-listen on a phone speaker and with headphones before approving.
